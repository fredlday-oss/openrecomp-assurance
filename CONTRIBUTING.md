# Contributing

Contributions must preserve fail-closed assurance semantics.

Before opening a PR:

1. add or update tests for behavioural changes;
2. do not weaken a comparison rule solely to make a fixture pass;
3. state whether a claim is PROVEN, BOUNDED, or CANDIDATE;
4. include provenance for new fixtures;
5. confirm all fixture material is lawful to redistribute;
6. avoid architecture-specific fields in shared schemas unless namespaced and justified.
